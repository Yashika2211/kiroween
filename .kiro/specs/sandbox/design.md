# Design: Sandbox

`backend/necromancer/sandbox/runner.py` drives the Docker CLI with `asyncio.create_subprocess_exec`
(argument lists only, never a shell string).

```
SandboxRunner
 ├─ available() -> bool                 # `docker info` with a 5 s timeout, cached
 ├─ install(job_id, repo_dir) -> RunResult
 │     docker run --rm --name necro-<job>-install
 │       --network bridge  -v necro-<job>-venv:/venv  -v <repo>:/src:ro
 │       python:3.12-slim  sh /src/.necro/install.sh
 ├─ test(job_id, repo_dir) -> RunResult
 │     docker run --rm --network none --read-only --tmpfs /tmp:size=64m
 │       -v necro-<job>-venv:/venv:ro -v <repo>:/src  -w /src
 │       python:3.12-slim  /venv/bin/python -m pytest -q -x --no-header -p no:cacheprovider
 └─ cleanup(job_id)                      # docker rm -f + docker volume rm
```

The install script is generated by Necromancer (not taken from the repo) and only runs
`python -m venv /venv` and `pip install` against the requirement files Necromancer wrote.
Installing the repo itself (`pip install -e /src`) also happens inside the container, so
`setup.py` only ever executes in the sandbox.

Common flags for every run: `--cap-drop ALL --security-opt no-new-privileges --memory 1g
--cpus 1 --pids-limit 256 --user 1000:1000 --env HOME=/tmp`.

Output is read incrementally and kept in a ring buffer so a noisy test run can't exhaust memory.
`RunResult.tail` is what the UI shows.
